## 五、不阻塞的三点

每条后面写不处理的最坏后果、普通运行能不能碰到。

1. **「原因」行里 code 显示成「[已隐藏]」。** broker 现有的脱敏规则把长下划线串当成密钥隐藏，不是本补丁引入的。最坏后果：用户想拿 code 去搜资料时看不到原文，中文标签和改法不受影响。每次这两类报错都会碰到。
2. **不带 code、只有英文原文的额度用完报错认不出**，照旧显示为一般上游报错。这是任务书「只按 code 认」的结果，方案第五节已写明。最坏后果：那一次看不到中文说明和改法，stop-access 也不触发。碰到的概率我没有数据。
3. **运行已经失败之后才接入（例如事后 `cxb wait`），看不到中文原因。** 这时只显示两行：

   ```
   [cxb] 失败原因：{"error":{"message":"User subscription sharing currently supports only …（other）
   [cxb] 改法：改用 Codex 自己的登录或 API key；已经出过这个错的线程请新开线程。
   ```

   「失败原因」行是按最终轮的报错原样打的，不走标签，所以没有中文原因，括注「（other）」也还在（运行中接入时这一行同样带「（other）」，但上面已经有中文三行）。这是我的方案和上一轮审查没覆盖到的：方案只要求这条路径补改法行，执行块照做了。最坏后果：这种接入方式下用户只看到英文正文加中文改法；`cxb show` 和运行中接入都有完整的中文三行。只有运行失败后才接入时会碰到。要补的话是一个小提交：失败收尾补改法行时，前面先补一行标签，约 3 行加一条用例。
